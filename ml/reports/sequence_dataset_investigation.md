# CNN/LSTM dataset investigation - 2026-11-13

Only documentation and small metadata were read. No dataset archive was downloaded. No CNN or LSTM was trained. The 48-column synthetic table is not chronological data and must not be reshaped into fabricated sequences.

Does not cover typing or motion modalities. |

Counts above are source-reported, not measured locally. No candidate has verified native genuine/uncertain/anomaly or coercion labels. Compatibility assessments are engineering inferences, not completed experiments.

Recommended next step: review HMOG's research terms or approve a limited BB-MAS phone subset after confirming size. Inventory subjects, sessions, timestamps, channel units, sample rates and missingness before model design. Preserve user/session boundaries, keep evaluation subjects separate from development subjects, and reserve chronologically later sessions for verification. Never randomly split overlapping windows across train/test. Fit normalization only on training data. Establish genuine/impostor pairing and a validation-calibrated uncertainty policy; do not invent an uncertainty label or label normal movement as coercion.

For CNN, use time-by-channel windows with explicit sampling/masks. For LSTM, retain chronological windows and reset state at true session boundaries; a gap between days is not a continuous sensor stream. Report FAR, FRR, EER, ROC-AUC, latency and detection delay on real users. Android currently stores gesture summaries and asynchronous motion samples, so future raw sequence capture needs its own privacy-preserving, versioned contract and consent review. No such collection expansion was made here.
